# 事故记录：aipro 断网 (2026-08-10)

## 概述

| 项目 | 内容 |
|------|------|
| **日期** | 2026-08-10 |
| **影响** | aipro (升腾 ARM 开发板) 完全断网，SSH 不通 |
| **根因** | sing-box tun 模式 `strict_route: true` + `auto_route: true` 接管了系统路由表 |
| **修复耗时** | 约 8 小时 |
| **数据损失** | 无（NVMe 数据盘未受影响） |

## 事故背景

aipro 是一台升腾 ARM 开发板，双盘架构：
- **TF 卡** (114.9GB ext4) = 系统盘（root, /etc, /home）
- **NVMe** (931GB) = 数据盘（/mnt/disk，用户数据 + sing-box 二进制）
- **无带外访问**：唯一的网络连接是 wlan0（WiFi），没有串口/IPMI/带外管理

## 事故经过

### 1. 部署 sing-box（tun 模式）

在 aipro 上部署 global-net-proxy 客户端，使用 **tun 模式**：
- `inbounds`: `type: "tun"`, `auto_route: true`, `strict_route: true`
- systemd service: `User=root`, `Restart=always`
- 配置为开机自启（`systemctl enable`）

### 2. 断网

sing-box 启动后：
- `strict_route` 接管了系统路由表
- `auto_route` 修改了所有路由规则
- 主网卡 wlan0 的路由被覆盖
- **SSH 完全不通**，无法远程修复
- 奇怪的是 wg 隧道到 lwtop 还活着（10.0.0.5 能 ping 通），但 aipro 本身的网络不通了

### 3. 开机自启 = 灾难放大器

即使重启 aipro 也救不了——systemd 会自动启动 sing-box，再次破坏路由表。
`Restart=always` 意味着即使进程崩溃也会自动重启。
`User=root` 意味着禁用用户账户也无效。

## 修复过程

### 尝试 1：macOS 上操作 ext4（失败）

- aipro 的 TF 卡插到 Mac
- macOS 15.7.5 SIP 锁死块设备写入
- `brew install ext4fuse` 超时，MacFUSE 无法安装
- **结论：macOS 无法写 ext4**

### 尝试 2：Windows 上操作 ext4（失败）

- TF 卡插到 lwwin (Windows)
- Python ctypes + PowerShell .NET + dd.exe
- 大偏移（>4GB）读取不到，更无法写入
- 定位了 service 文件的磁盘偏移，但无法写入
- **结论：Windows 无法可靠操作 ext4**

### 尝试 3：lwpc 上挂载 TF 卡（成功）

- TF 卡插到 lwpc（Ubuntu Linux）
- `sudo mount /dev/sdc2 /mnt/aipro` 成功
- 通过文件系统操作完成所有清理

### 清理操作（在 lwpc 上）

```bash
# 删除 sing-box systemd service
sudo rm /mnt/aipro/etc/systemd/system/sing-box-gnp.service
sudo rm /mnt/aipro/etc/systemd/system/multi-user.target.wants/sing-box-gnp.service

# 删除 /home/lwboy 软链接（断开 NVMe 链）
sudo rm /mnt/aipro/home/lwboy   # 这是一个指向 /mnt/disk/lwboy 的软链接

# 创建紧急用户
sudo ... # 在 /etc/passwd, /etc/shadow, /etc/group 中添加 aipro_emergency (UID 2000)
# 设置 sudo NOPASSWD, 添加 SSH key
```

### TF 卡回插 + 验证

- TF 卡插回 aipro
- aipro 上电启动
- 确认 sing-box service 不存在，不会自启
- aipro 网络恢复正常

## 教训

### 1. 无带外访问的机器绝不用 tun

> 这是最核心的教训，也是本仓库存在的原因。

tun 模式的 `strict_route` + `auto_route` 会接管路由表。在以下条件下是致命的：
- 没有带外管理（IPMI/iLO/串口）
- 唯一的网络连接是 SSH
- 开机自启

**解决方案**：使用 mixed 代理模式，只开 socks5+http 端口，不碰路由表。

### 2. 开机自启是放大器

`systemctl enable` + `Restart=always` 意味着：
- 重启不能修复（service 会再次启动）
- 进程崩溃会自动重启
- 唯一的修复方式是物理操作磁盘

**解决方案**：`Restart=on-failure`（非 always），`User=普通用户`（非 root）。

### 3. User=root 的服务无法通过禁用用户来停止

即使禁用运行 sing-box 的用户账户，root 服务仍会执行。
必须删除 service 文件本体。

### 4. 双盘架构的软链接是关键

aipro 的 `/home/lwboy` 是指向 NVMe 的软链接。
删除软链接可以断开 NVMe 上程序的启动链，而不影响数据。

### 5. ext4 在非 Linux 上不可靠

macOS 和 Windows 都无法可靠操作 ext4 文件系统。
必须有一台 Linux 机器来修复 ext4 磁盘。

## 修复后的架构变更

| 变更项 | 旧（tun 模式） | 新（mixed 模式） |
|--------|---------------|-----------------|
| inbound | tun (接管路由表) | mixed 0.0.0.0:1080 |
| 权限 | root | 普通用户 |
| Restart | always | on-failure |
| 路由表 | strict_route + auto_route | 不碰 |
| 断网风险 | 高 | 零 |
| WireGuard | system:true (内核态) | system:false (userspace) |
| DNS 格式 | address 字段（旧） | type + server 字段（新） |
| ruleset download_detour | wg-out | direct（避免鸡蛋问题） |

## 验证

新配置在 aipro 上验证通过：
- sing-box 1.13.16
- mixed inbound `0.0.0.0:1080`
- wireguard endpoint (system:false, userspace)
- route: ip_is_private → direct, final → wg-ep
- GitHub / Google 通过代理可访问
- 国内网站直连正常
- **无 tun, 无 strict_route, 无 auto_route**
